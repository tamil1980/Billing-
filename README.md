# Billing Software (MERN — single Render service)

Full-stack billing/invoicing app: **React + Vite** frontend served by an **Express + MongoDB Atlas** backend.
One codebase, one Render web service.

```
├── backend/          Express REST API (Mongoose models + routes)
├── frontend/         React + Vite SPA (billing, invoices, items, suppliers, users)
├── dist/             Built SPA (generated by `npm run build`, served by Express)
├── vite.config.js    Builds `frontend/` into `dist/`
└── render.yaml       Render blueprint
```

## Run locally

```bash
npm install                 # installs everything at the root
npm run build               # builds the React app into dist/
# create backend/.env (see .env.example) with your MongoDB Atlas URI
npm start                   # http://localhost:5000 — serves API + built app
```

For frontend hot-reload while developing:

```bash
cp frontend/.env.example frontend/.env.local   # VITE_API_BASE_URL=http://localhost:5000
npm run dev:web                                 # Vite dev server on :5173
```

In production `VITE_API_BASE_URL` is left empty, so the app calls the API on the
same origin it's served from (no separate backend URL needed).

## MongoDB Atlas setup

1. Create a free cluster at https://www.mongodb.com/atlas
2. **Database Access** → add a database user + password.
3. **Network Access** → allow `0.0.0.0/0` (anywhere) so Render can connect.
4. **Connect → Drivers** → copy the connection string:
   `mongodb+srv://<username>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority`
5. Set it as `MONGODB_URI`.

On first boot the backend seeds demo accounts automatically:

- Admin: `admin@admin.in` / `admin123`
- User:  `user@admin.in` / `user123`

## Deploy to Render (single web service)

This repo contains a `render.yaml` blueprint, so the easiest path is:

1. Push this folder to GitHub (make sure **node_modules, dist, .env are NOT committed** —
   they're in `.gitignore`).
2. In Render: **New → Blueprint**, select the repo, confirm the service.
   Or **New → Web Service** with:
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm start`
3. Add environment variables:
   - `MONGODB_URI` = your MongoDB Atlas connection string (required)
   - `CORS_ORIGIN` = `*` (or your app URL)
4. Deploy. The same URL serves the app *and* the `/api/*` endpoints.

## API endpoints

| Method | Endpoint            | Purpose                          |
|--------|---------------------|----------------------------------|
| GET    | `/api/items`        | List inventory items             |
| POST   | `/api/items`        | Add an item                      |
| DELETE | `/api/items/:id`    | Delete an item                   |
| GET    | `/api/suppliers`    | List suppliers                   |
| POST   | `/api/suppliers`    | Add a supplier                   |
| DELETE | `/api/suppliers/:id`| Delete a supplier                |
| GET    | `/api/invoices`     | List invoices                    |
| GET    | `/api/invoices/:id` | Get one invoice (with line items)|
| POST   | `/api/invoices`     | Create an invoice                |
| GET    | `/api/users`        | List users                       |
| POST   | `/api/users`        | Add/register a user              |
| DELETE | `/api/users/:id`    | Delete a user                    |
| POST   | `/api/auth/login`   | Login                            |

## Notes

- Passwords are hashed with bcrypt in MongoDB.
- If the old `Billing-software` / `Billing-frontend` repos have committed `node_modules`,
  delete it from git (`git rm -r --cached node_modules`) — Windows-created bin scripts
  cause "vite: Permission denied" on Render's Linux machines. This repo does not have
  that problem.
